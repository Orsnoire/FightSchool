# Human recoloring assets

Each of the four approved source views has a neutral RGBA base and three
exclusive, 8-bit grayscale PNG masks. All files use the original 1024 × 1536
canvas with no crop, resize, rotation, or changed alpha. Paths and SHA-256 hashes
are recorded in the parent manifest and `build-report.json`.

| Channel | White mask pixels select | Black mask pixels exclude |
| --- | --- | --- |
| Hair | Scalp hair and eyebrows | Other regions, eyelashes, solid ink |
| Eyes | Irises | Pupils, whites, highlights, outlines |
| Skin | Visible face, ears, neck, arms, hands | Clothing, hair, eyes, solid ink |

Masks are data textures, not visible overlays or opacity replacements. Their
values are 0 or 255; antialiasing and silhouette coverage remain in the base.
The renderer must preserve base alpha and must not apply it a second time.
Do not independently resize or filter masks and bases.

## Build and preview

From the repository root after `npm ci`:

```sh
npm run build:avatar-assets
npm run preview:avatars
```

Open `http://127.0.0.1:4178` for model/view selection, eight choices per color
channel, randomization, diagnostic colors, and individual masks. This is a local
art workshop; it does not save student data or integrate the live portrait UI.

The build uses the original source files and checked-in `regions/` maps to
reproduce all masks, neutral bases, report hashes, and sixteen ignored PNGs in
`previews/`. The checked-in `preview-sheet.png` is the reviewed contact sheet:
male front, female front, male combat, female combat in rows; diagnostic,
light, dark, and mixed palettes in columns. It is a review artifact and is not
regenerated by the asset build.

## Source registration and shading

Image-generated diagnostic recolors supplied semantic guides. Because generated
edits can move outlines slightly, `scripts/avatar/refine-region-guide.mjs`
registered those guides against the original painted pixels. The resulting
reviewed region maps are the reproducible build inputs: magenta means hair,
yellow irises, green skin, and black unchanged. The guide-refinement script is
specific to these brown-haired, warm-skinned originals; it is not a general
segmentation algorithm. New artwork needs a new reviewed region map.

Within each region, the neutral base derives grayscale shading from the original
red channel divided by that region's 99th-percentile red value, clamped to white.
This removes the source hue while retaining its shadow variation. Every
unselected RGB byte and every alpha byte remains identical to the original.
This is an artist-oriented shading approximation, not reconstruction of hidden
line-art or lighting layers.

`shared/avatar-recolor.mjs` multiplies neutral RGB by the selected sRGB swatch in
each masked region. It leaves all other pixels unchanged and has no DOM or Node
dependencies. The same function powers the generated previews and local canvas
preview. A production renderer can reuse it or implement the equivalent shader;
resolve persisted color IDs through the versioned palettes before rendering.

## Remaining animation work

Recolor-ready does not mean rig-ready. Starter clothing is still painted into
the assembled views. Animation and interchangeable equipment require separate
body and clothing parts, reconstructed overlap beneath joints, calibrated
pivots, hand grips, and near/far draw order. The front and combat illustrations
are separate references, not a continuous turn animation. Rig and equipment
transforms remain unset until that art exists.
