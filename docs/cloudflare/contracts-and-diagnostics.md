# Contracts and diagnostics (C04)

C04 preserves the current combat rules, saved-room format, session revocation,
owner checks, reward receipts and the accepted waiting-room HP preview. It adds
no migration and performs no production data operations.

## Boundary ownership

- `shared/contracts/fights.ts` owns the teacher authoring validator used by the
  form and HTTP route: text/array/number limits, registered enemies/AI, unique
  groups and at most 120 individuals. The existing tier/default normalization
  remains on the server. Registered built-in loot IDs and UUIDs share the ID
  contract; the repository still verifies ownership for every custom UUID.
- `shared/contracts/dto.ts` owns JSON transport types independently of Drizzle.
  Teacher and fight timestamps are milliseconds; private student credentials,
  remembered loadouts and revision fields are absent. Compatibility exports in
  `shared/schema.ts` preserve callers during later domain extraction.
- `shared/contracts/combat.ts` owns discriminated command shapes, public state
  field lists, earned results and server message types. Unknown command fields
  are stripped (a forged leave target cannot change socket identity). Required
  command IDs, rounds and payload bounds are validated. Auth/session revocation
  and host/member authorization remain server-side on every command.
- `worker/combat/public-snapshot.ts` selects allowed root/player/enemy/nested
  fields. New internal fields are private by default. Submitted answers,
  question fingerprints, departed participants, enemy AI and hidden flatten
  buffs remain private. Questions/results also use explicit projections,
  including the separate game-over message. Saved rooms are not rewritten.
- `client/src/lib/apiQueries.ts` provides typed dashboard, guild and leaderboard
  query factories with separate cache keys and encoded URLs. Existing unrelated
  queries retain their behavior; broader route/service extraction is C09–C11.

## Parsing and errors

All Worker JSON body readers use `worker/http/json.ts`: 1 MiB for fight authoring,
16 KiB for teacher authentication, and 64 KiB for other JSON inputs. The streaming
reader counts UTF-8 bytes, enforces actual bytes when Content-Length is missing
or false, and cancels oversized streams. Invalid JSON returns 400; oversize 413.
Empty bodies are allowed only where the existing host-launch contract allows it.
Binary object uploads retain their separate upload checks.

WebSocket commands are text with at most 16,000 UTF-8 bytes. Parse errors do not
quote submitted JSON. Only deliberate `CombatRuleError` rejections are sent to
clients; unexpected dependency exceptions receive a generic message. Existing
receipts, expired-session closure, serialized commands and retry behavior remain.

## Diagnostics

`worker/diagnostics.ts` emits JSON with an explicit field allowlist:
`event`, `outcome`, generated `requestId`, `roomId`, `revision`, `status`,
`durationMs`, and `queueMs`. HTTP request IDs are generated by the Worker,
returned to the caller, and forwarded to socket attachments. Socket diagnostics
identify the connection request (or a generated fallback for saved attachments).
Checkpoint timing and quest-evidence success/retry events preserve retry behavior.

No raw URL/query, request body, submitted answer, cookie, token hash, credential,
actor name, SQL or exception object is logged. Existing room/command execution
remains serial. C05–C06 own detailed cost comparisons and optimization; these
logs alone are not evidence of lower latency. They add some logging volume,
which must be observed with the next authorized release.

## Intended required CI checks

Before merging a cleanup PR, require these successful checks on its exact head:

| Workflow / job | Coverage |
| --- | --- |
| CI / verify | Clean Node 22 install, typecheck, complete tests (including schema and contract gates), client and Worker builds |
| Combat UI Acceptance / browser | Chromebook/phone combat overlays, host UI and session workflows |

Both workflows now run on every pull request. The browser workflow's former
path filter could otherwise leave an intended required check missing/pending.
Live deployment/acceptance remain separate, explicitly authorized workflows;
C12 owns release pinning, isolated fixtures and recovery drills.

**Enforcement limit:** the October 12 branch API reports `main.protected=false`
and no required contexts. The connector has no administration write capability;
this change documents the intended merge policy and ensures checks are emitted,
but does not claim repository protection has been enabled.
