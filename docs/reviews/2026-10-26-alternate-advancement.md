## Earning sensitivity

A controlled reward example (16 correct, 4 incorrect, 40 actual damage, 10 actual blocking, 10 actual healing, 20 base) yields 92 raw XP. Adding 30 actual damage, blocking or healing adds exactly 30 raw XP; when entirely overflow at full stamina this is 0.5 AA. If the job still needs XP, only the excess enters the AA bank. Existing stamina and fractional carry remain in the original SQL award procedure.

Higher damage may end fights earlier; actual damage is bounded by enemy HP, healing by missing HP, and blocking by incoming attacks. The table cannot predict how many questions students will answer or how many fights they will play. Dodge grants no synthetic blocked-damage reward, so dodging can reduce contribution XP. No new earning formula, contribution cap or multiclass penalty is introduced.

## Interpretation and release limits

- Tier 1 breadth still gives a veteran more power than a new character. This is the owner-approved growth model; rank caps are not parity between students.
- Primary-stat formulas multiply several abilities, so the high-rank action values grow sharply. Costs and tier limits are retained as explicitly requested; damage-to-MAT/RTK weapon specialization does not rewrite class attack formulas.
- Migration 0018 is additive and unshipped. It keeps cumulative overflow/fractional XP and legacy assignments. Purchases and awards take the same student row lock; purchase receipts prevent retries charging twice.
- Runtime rollback must retain 0018 data and use a compatibility build that keeps the paid appearance guards. Pre-AA code could bypass paid editing, so rolling all the way back to that runtime is not a safe functional rollback after purchases begin. Never drop wallet/ledger columns to roll back.
- Campaign PR #81 is separate. Its adapter must pass the stricter campaign/guild power limit through `aaTier`, freeze it per encounter, and reconcile its migration number before the two branches merge. Classroom fights use their persisted hosting-guild power cap now.
- Classroom pacing, physical-device observation and production migration/deployment acceptance remain future observations; this report is deterministic local analysis.
